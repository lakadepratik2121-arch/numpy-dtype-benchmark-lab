Memory scales with bytes per element

An array's size in memory is its element count times itemsize. Dropping from int64 to int8 cuts a 1M-element array from 8 MB to 1 MB, an 8x saving, with no code change beyond astype().

Smaller is not always faster

Time to multiply a 1M-element array by 2, best of several runs. The scale is logarithmic, because float16 is so much slower that a linear scale would hide everything else. Most CPUs have no native float16 arithmetic, so NumPy emulates it.

Which dtype should I use?

Choose the smallest type that safely holds your data's range, then measure on your own workload.

uint8Image pixels (0-255). A float64 image uses 8x the memory of the same uint8 image.
int8 / int16Small counts, ratings, flags. Check the range with np.iinfo first.
int32 / int64General integers and indexes.
float32Large machine-learning and image arrays where memory matters.
float64Scientific and financial maths that needs accuracy.
float16Storage only. Slow to compute with and overflows at 65,504.
